# 净罩 · 餐饮后厨排烟罩清洗与验收平台

管理门店、罩体分段、滤网、风管点位、清洗周期、停灶窗口、施工人员、前后照片、油污等级、复装检查与结算单的全流程平台。

## 一条命令启动

```bash
npm start            # 等价于 node run.js，首次自动建库并写入 正常/返工/拒签 三样例
npm start -- --reset # 重置数据库与样例
npm test             # 运行规则测试（node --test，无需安装任何依赖）
```

启动后访问 **http://localhost:5180/** ，页面右上角切换身份体验不同角色视角。

- 运行要求：Node.js ≥ 22.5（使用内置 `node:sqlite` 与 `node:test`，**零 npm 依赖**）
- SQLite：`data/hoodcare.db`（工序记录与结算快照）
- 现场照片/签名：本地目录 `data/photos/`
- 到期/超时提醒：进程内每 5 秒扫描落库，前端轮询推送
- 风量测试：模拟适配器 `src/airflow.js`（按点位场景给出确定性读数，可替换为真实仪表驱动）

## 核心业务规则

1. **排班互斥**：停灶窗口必须经门店确认后才能排班；排班时段须落在窗口内；同一门店厨房同一时段只允许一个工单（两个班组不能占用同一厨房时段）。
2. **步骤顺序**：每段严格按 拆卸→清洗→干燥→复装→试运行 推进，不可跳步、不可重复登记；拆卸时必须登记滤网数量与油污等级，复装时必须登记滤网复装数。
3. **增项确认**：重油污（油污 ≥Ⅳ 级）与滤网损坏自动生成待确认增项，**必须门店经理确认**后才计入结算；施工人员与财务均无权确认。
4. **验收权限**：验收结论只能由验收员提交，施工人员/财务 403；漏装滤网、缺前后照片、照片角度超差（±10° 参考线容差）、风量复测未通过、存在未闭环异常时无法提交验收。
5. **结算幂等**：门店签字后由财务生成结算快照，金额 = 实际清洗段数 × 单价 + 已确认增项；同一工单重复请求返回同一快照（数据库唯一约束兜底），快照生成后不可变。

异常分别处理：临时营业（工单挂起/复工）、重油污加项、滤网损坏、照片角度不合格（重拍合格自动闭环）、施工超时（进程内扫描产生异常与提醒）、复测噪声异常（复测合格自动闭环）、门店拒签（协商后重新签字）。

## 页面

- **工作台**：状态统计、到期与超时提醒、最近工单
- **周期计划**：清洗周期、到期倒计时、是否已安排工单
- **停灶协调**：窗口申请/确认/驳回、排班（互斥校验）
- **施工工单**：罩体分段示意条（完成度从左到右推进，替代普通卡片）、分段施工单、照片对照（统一拍摄角度参考线）、风量复测、异常与增项
- **门店签字**：大触控签名区（加粗笔迹，适配戴手套操作）、拒签入口
- **费用复核**：结算快照明细、财务复核

视觉：不锈钢灰 + 炭黑 + 清洁绿。

## 测试

`npm test` 覆盖：排期互斥（未确认窗口/时段冲突/跨门店）、步骤顺序（跳步/重复/未开工）、增项确认（角色/状态机/异常闭环）、验收权限（403 + 门禁拦截项）、结算幂等（重复请求同快照/金额构成/唯一约束），以及临时营业挂起、拒签重签、返工轮次、超时提醒幂等。

## 目录结构

```

src/seed.js         示例数据（正常/返工/拒签）
public/             前端 SPA（原生 JS，无构建）
test/rules.test.js  规则测试
data/               SQLite 与现场照片（运行时生成）
```
